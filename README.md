# 夢小説シチュガチャ

フォルダー一式を同じ場所に置き、`index.html` をダブルクリックして利用できます。

ガチャでは「原作準拠・現代パロ・学園パロ・制限なし」から世界観を選べます。原作準拠では、電車・スマートフォン・コンビニなどを前提とするシチュエーションを自動で候補から外します。夢主設定は共通設定に加えて作品別にも編集でき、完成プロンプトには選択キャラの作品に対応する設定だけが追加されます。「今回だけの追加指定」は今回のプロンプトに加わります（従来の「自由な追加指定」と同じ欄です）。

## 文章の好み・舞台・補足設定集（v42）

ガチャ画面の「夢主設定・シチュ候補・固定プロンプトを編集」内にある「文章の好み・舞台・補足設定集」で登録します。空のままなら、従来どおりのプロンプトを生成します。個人の追加文を自動分類・移動することはありません。

v43 から、現パロ、学パロ（大学・専門学校）、オフィス、カフェ、シェアハウス、芸能界、バンド、王宮・貴族、騎士・冒険者、魔法学園、和風あやかし、大正浪漫風、近未来SF、転生現パロの **14種類の舞台設定** を初期登録します。ガチャ上部の「舞台設定」から選ぶと、その設定文だけがプロンプトへ加わります。初期選択は「指定なし」です。設定文は [stage-presets.js](stage-presets.js) にあり、登録後は画面で自由に編集・無効化できます。

初期文は舞台の生活環境・描写の手がかり・翻案方針を示し、夢主の詳しい経歴や二人の恋人関係は固定しません。学パロは既存の成人夢主設定に合わせた大学・専門学校が基本です。作品固有の正本や詳しい独自設定は、作品・舞台を限定した補足設定として追加できます。

既存環境への初期舞台の追加は v43 未満からの移行時に行い、同じIDの編集済み・無効化済み設定は置き換えません。過去の生成記録や、保存条件の再利用中に使う設定集には追加しません。再利用中に初期舞台を使いたい場合は「現在の設定集に戻す」を押してください。

| 入れる場所 | 用途・例 |
| --- | --- |
| 文章の好み | 毎回使う個人の文章上の希望。「即答」という表現を避ける、など。専用の保存ボタンで保存します。 |
| 舞台設定 | ジョジョのオフィス現パロなど、今回使う独自の舞台。ガチャ上部で一つ選びます。 |
| 補足設定 | 作品・部・キャラ・世界観・舞台に合う回だけ使う指定。例：作品をジョジョ、部を5部に限定した地名表記。 |
| 夢主の差分 | 特定の舞台での職業など。共通・作品別設定に「追加」するか、両方を丸ごと「置き換える」か選べます。置き換える場合は年齢・口調など残したい内容も含めてください。 |
| 今回だけの追加指定 | 今回のシチュでだけ加えたい内容。繰り返し使う文は設定集に登録すると選び直せます。 |

舞台は対応する世界観モードを持ち、選択時にそのモードへ切り替わります。選択なしへ戻した場合は世界観モードを維持します。舞台の対象とキャラ・世界観が合わなくなった場合は生成を止め、どちらかの選び直しを案内します。

補足と夢主の差分は「条件に合えば自動」または「条件に合う回で手動選択」にできます。作品・部など異なる項目はすべて一致する必要があり、一つの項目で複数選んだ場合はいずれかの一致で適用します。何も選ばない項目は限定なしです。「5部」のような部名は作品とセットで指定してください。キャラはID、作品・部は名前の完全一致で判定するため、名称やIDを変更したときは適用条件も確認してください。

生成ボタンの上の「今回適用する設定」で、適用理由・設定本文・版・参考資料を確認できます。自動適用を今回だけ外す、手動設定を選ぶ操作もここで行います。選択・除外は次のガチャや再読み込みにも引き継ぎます。夢主の置き換えが複数重なった場合は一つに絞ってから生成します。「今回の分量・視点」は入力後に「分量・視点を適用」を押してください。

参考資料は名前・版・抜粋を保存できます。資料本文を渡したい場合は、必要な内容を抜粋欄へ貼り付けてください。資料名だけなら「このプロンプトに本文は含まれていない」という参照指定になります。ChatGPT Libraryや外部ファイルの自動取得は行いません。

生成した時点の設定集・選択・除外・出力指定を完成プロンプトと一緒に記録します。保存条件や小説から再利用した場合は、その時点の設定集を使います。現在の設定集へ切り替える場合はガチャ上部の「現在の設定集に戻す」を押し、舞台・手動適用・除外を選び直してください。補足情報がない旧保存条件の再利用では、現在の補足や文章の好みを勝手に追加しません。

設定は同じブラウザー内に保存され、完全バックアップ version 3 に含まれます。旧バックアップ version 1・2 も読み込めます。履歴の再利用で条件を変えた場合にも当時の適用判定ができるよう、生成時の設定集は全文を複製して保存します。大きい資料は必要部分を抜粋し、保存容量エラーが出た場合は登録を成功扱いにせず入力を残します。設定を一時停止するときは「この設定を有効にする」を外してください。保存済みの小説・条件の記録には影響しません。

既存の候補は文字列配列のまま維持しています。この版ではシチュ候補そのものへの補足の紐付けは追加していません。特定シチュ用の文は手動の補足または今回だけの追加指定で扱えます。

## 固定プロンプト

標準の固定プロンプトは **Ver.0.1.3.3** です。全文は [`prompts/dream-novel-0.1.3.3.md`](prompts/dream-novel-0.1.3.3.md) に保存し、ファイルをダブルクリックして使えるよう `seed-data.js` にも同じ文面を収録しています。テストで両者の一致を確認します。

Ver.0.1.3.3 では「夢主と関係性」の直後に「脇役の登場と場面の把握」を追加しました。同席する脇役の存在・名前・呼称と、途中から加わる人物を自然に把握できるようにする、ユーザー指定の2段落をそのまま収録しています。旧版 [`prompts/dream-novel-0.1.3.2.md`](prompts/dream-novel-0.1.3.2.md) は履歴として保持します。

旧標準文と一致する設定は起動時に新版へ更新します。独自に編集した固定プロンプト、保存条件、生成済みプロンプトの履歴、保存済み小説は今回の更新で書き換えません。

## ライブラリ登録とプロンプトの版管理（v41）

AIの出力をタイトルごと「小説をタイトルごと貼り付け」へ貼ると、空の登録フォームでは1行目がタイトル、2行目以降が本文に分かれます。本文の空行・末尾改行は保持します。本文だけを貼るときは自動分離のチェックを外してください。タイトルは登録前にも、保存後の「編集」からも変更できます。

小説には生成時の条件と完成プロンプトを保存します。「一緒に保存するプロンプトを確認」で登録対象を確認できます。別のガチャや設定変更で、保存済み小説のプロンプトは書き換わりません。外部AI側だけで変更したプロンプトは自動取得できません。

固定プロンプトは「設定を保存」または「プロンプトを生成」した時点で版を記録します。任意の版名、版ID、固定文、比較基準の配布標準文、日時を保存し、履歴から再利用できます。同じ文面・版名・比較基準の再保存では履歴を重複させません。この版管理機能の導入時には、標準 Ver.0.1.3.2 本文を変更していません。

差分は「配布標準 → 自分の固定文」と「自動結合後 → 完成欄での追加編集」を分けて表示します。通常のガチャ条件の追加は、標準文を編集した扱いにはしません。比較基準はアプリ収録の標準版であり、サーバから随時取得する最新状態や、既存カスタム文の派生元を保証するものではありません。過去の版情報がない小説は、冒頭の版表記があっても「版情報未記録」のままです。新しい版履歴も完全バックアップに含まれます。

閲覧画面の「アノテーション用に書き出す」には次の2種類があります。

- **本文だけTXT**：夢アノテーターの「新規作品 → ファイル」から追加。プロンプトや生成条件を注釈対象の本文に混ぜません。アノテーター側のOLD/NEWは利用者が選ぶ分類で、実際の固定プロンプト版とは別です。
- **本文＋プロンプト・版情報JSON**：`dream-gacha.novel-export` version 1。本文、キャラ・条件、完成プロンプト、版記録をAI分析・保管に使えます。これは現行アノテーターのJSON復元形式ではありません。現行の復元は全件置換し、版情報もOLD/NEWに変換するため、直接インポートしないでください。注釈は含まれず、評価の実施状況は不明として出力します。

3サイト統合、自動同期、アノテーター側の改修は今回の変更に含めません。

## キャラデータの更新

お気に入りは端末ごとの設定です。配布用の初期キャラJSONでは `favorite: false` とし、ビルド時にも全件解除します。更新時に端末へ保存済みのお気に入りは変更しません。

作品別の初期キャラデータは `data/characters/` にあります。JSONはアプリのキャラ入出力と同じ `schema: "dream-gacha.characters"`、`version: 1`、`characters` 配列の形式です。作品を追加するときは、同じ形式のJSONをこのフォルダーへ追加し、各キャラに重複しない `id`、`name`、`work` を指定してください。タグはアプリに表示される共通タグだけを使い、身長不明は `heightCm: null`、`heightStatus: "unknown"` とします。

Node.js 18以降が入っているWindowsでは `キャラデータを更新.bat` をダブルクリックすると、JSONを検証して `character-data.generated.js` を生成できます。コマンドラインでは `node tools/build-character-data.js` を実行します。JSON構文、schema/version、必須項目、ID重複、同じ作品の同名重複、許可外タグ、身長4項目（表示・数値・状態・出典）の整合性を検査します。失敗した場合は内容を確認してJSONを修正してから再実行してください。

`character-data.generated.js` は公開用の生成ファイルです。直接編集せず、作品別JSONを更新してからビルドしてください。`index.html` はこの生成ファイルを `seed-data.js` より先に読み込むため、ファイルをダブルクリックする従来の起動方法もそのまま使えます。

設定はブラウザーの localStorage、夢小説は IndexedDB に保存されます。完全バックアップは両方を一つの JSON に書き出し、どちらかの読み出しに失敗した場合はファイルを作りません。復元前に全内容を検証し、設定または夢小説の書き込みで通常のエラーを検出した場合は復元前のデータへ戻します。ブラウザー自体の強制終了など、二つの保存領域をまたぐ処理を中断された場合まで一括保証するものではありません。

画面からキャラJSONを更新するときは「作品単位で置換」が通常の導線です。JSONに含まれる1作品だけを入れ替え、ほかの作品と、同じキャラのお気に入り・アーカイブ・手動入力した身長を維持します。全キャラ置換は「高度な操作」にあります。

作品名と部・シリーズは複数選択と除外を併用できます。パソコンでは左クリックで選択、右クリックで除外します。スマートフォンではパネル内の「選択」「除外」を切り替えてから項目を押します。

旧形式（完全バックアップ version 1）に `novels` が含まれない場合、現在の夢小説アーカイブを維持します。新形式で `novels: []` が明示されている場合は、アーカイブを空にします。

## テスト

Node.js 18 以降で `node --test test/*.test.js` を実行します。

実画面の確認は `node tools/library-browser-check.mjs <インストール済みplaywrightのディレクトリ>` で実行できます。Chromeの一時プロファイルで実際の `index.html` を開き、貼り付け・タイトル編集・版履歴・TXT/JSON出力・完全バックアップ復元・390px幅を確認します。利用中のブラウザーや保存データは触りません。

新しい設定欄は `node tools/context-browser-check.mjs <インストール済みplaywrightのディレクトリ> [スクリーンショット保存先]` で検証できます。実フォームから登録し、条件判定・手動適用・除外・夢主競合・参照資料・生成時記録・再利用・保存失敗・復元・旧データ・表示上のエスケープ・390px/1280px幅・テーマを確認します。こちらも一時プロファイルを使います。
