# スマホUI改修 — 2026-10-16

## 目的と変更

iPhone 14相当の390×844 CSS pxを中心に、キャラを選ぶ・回す・コピーする操作を画面内で行えるよう整理した。

- **簡単モード**：キャラと4つの結果を表示。名前・作品・お気に入りからキャラを直接選ぶと、そのキャラが固定される。
- **カスタマイズ**：項目ごとの引き直し・固定、抽選候補、舞台、夢主設定、条件編集を表示。モード切替で内容を初期化しない。
- **アーカイブ**：「小説」「保存した条件」「新しく保存」に分け、最初に保存済みの作品を表示。長文の閲覧・編集は既存のスクロール領域を維持。
- **キャラ管理**：「一覧」「追加」「ファイル」に分け、詳細フィルタと一括操作を折りたたむ。結果は40件ずつ表示。「検索結果を全選択」は未表示分を含む検索結果全体が対象。
- スマホの下部ナビゲーションとガチャ操作ボタンを固定。入力文字は16px、主操作は44px以上の高さ。配色、アイコン、見出し、余白を揃えた。
- キーボード操作、ダイアログ内のフォーカス移動と復帰、動きを抑える端末設定に対応。ページの拡大は妨げない。

## 関連不具合の修正

- 小説の閉じるボタンへ渡るクリックイベントが、未保存確認を飛ばしていた。明示的な `true` だけを確認省略として扱う。
- キャラ選択の保存に失敗した場合、キャラ・条件・固定を元に戻し、選択画面を残す。
- 抽選候補が0件なら結果を一部だけ更新したり、前のキャラを使い回したりしない。該当する設定へ戻れるようにする。
- 小説の保存・削除で一覧が再描画された後にも、適切な操作へフォーカスを戻す。
- Safari系でタップしたボタンが `activeElement` にならない場合も、実際の起点ボタンを保持して復帰する。

## データと構成

既存のJavaScript構成を継続し、表示用の `src/app-experience.js` と `assets/mobile-ui.css` を追加。外部ライブラリや外部サービスは追加していない。

キャラの配布データ、固定プロンプト本文、保存条件、小説本文、生成時のプロンプト・条件の記録は変更していない。localStorageとIndexedDBの保存先、バックアップv4と旧版の復元互換性を維持する。表示モードだけは独立した `dreamGachaDisplayMode` キーに保存する。

## 操作の比較

比較元は `04a2f3e`。独立したテスト用ブラウザ、同じ乱数とデータ、390×844で測定。縦位置はページ上端からのCSS px。主操作以外の位置は登録内容により変わる。

| 操作・情報 | 改修前 | 改修後 |
|---|---:|---:|
| キャラ候補を開く | スクロール＋2タップ | スクロールなし・1タップ |
| キャラを選び、固定する | 最小4タップ | 最小2タップ |
| コピー操作 | 2,457px | 717px・下部固定 |
| 小説一覧の開始 | 2,096px | 254px |
| 管理画面の検索欄 | 794px | 271px |

キャラ選択のタップ数には検索文字の入力と候補一覧内のスクロールを含めない。

### 再実行

```powershell
node --test test/*.test.js
# $playwrightPath はインストール済みPlaywrightのパッケージディレクトリ。
node test/browser/mobile-ui-browser-check.mjs $playwrightPath output/mobile-ui
node test/browser/mobile-ui-browser-check.mjs $playwrightPath output/mobile-webkit http://127.0.0.1:4328 --webkit
```

WebKit実行時はPlaywright公式CLIでWebKitをインストールしておく。HTTP検証はリポジトリルートをローカルサーバーから配信する。公開確認時は末尾のURLを公開サイトへ変更し、一時プロファイルのまま実施する。

公開時にはPagesのビルド成功に加え、配信ファイルのSHA-256照合と公開URLでのモバイルテストを実施する。
